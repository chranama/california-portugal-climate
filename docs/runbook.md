# Runbook

This runbook covers local setup, pipeline execution, dashboard startup, artifact
inspection, validation, and cleanup.

For config, data, warehouse, model, and artifact contracts, see
[Workflow Interface](interface.md).

## Setup

```bash
uv sync --dev
```

Set local paths and Open-Meteo endpoints before running ingestion, orchestration,
or the dashboard:

```bash
export CLIMATE_DATA_ROOT=data
export CLIMATE_LOG_ROOT=logs
export OPEN_METEO_GEOCODING_BASE_URL=https://geocoding-api.open-meteo.com/v1/search
export OPEN_METEO_HISTORICAL_BASE_URL=https://archive-api.open-meteo.com/v1/archive
```

## Run Ingestion

Recent mode:

```bash
uv run fetch-daily-weather --mode recent
```

Backfill mode:

```bash
uv run fetch-daily-weather --mode backfill
```

## Run Local Verification

Use this command when refreshing the local evidence state:

```bash
uv run climate-verify-local
```

It runs recent ingestion, dbt build, baseline training, prediction, manual run
logging, observability rebuild, fast tests, integration tests, workflow-state
generation, evidence manifest generation, and evidence manifest validation.

## Build Warehouse

Run ingestion first when raw weather files need to be refreshed. If the raw data
already exists, the warehouse build can be rerun directly.

```bash
uv run climate-dbt-build
```

Equivalent explicit command:

```bash
cd dbt
uv run dbt build --project-dir . --profiles-dir .
```

If observability base tables are missing, initialize them explicitly:

```bash
uv run climate-init-observability
```

## Train And Predict

```bash
uv run climate-train-baseline
uv run climate-predict-baseline
uv run dbt build --project-dir dbt --profiles-dir dbt --select observability
```

Inspect:

- `models/baseline_rf_metrics.json`
- `data/mart/predictions/baseline_rf_predictions.csv`
- `proof/workflow_state.latest.json` after `uv run climate-verify-local`

The observability rebuild refreshes dashboard summary tables after training logs
new ML metrics.

## Run Orchestration

Daily flow:

```bash
uv run python -m climate_pipeline.orchestration.prefect_flow daily
```

Backfill flow:

```bash
uv run python -m climate_pipeline.orchestration.prefect_flow backfill \
  --start-date 1980-01-01 \
  --end-date 2024-12-31
```

Optional checks:

```bash
uv run python -m climate_pipeline.orchestration.prefect_flow daily \
  --with-dbt-tests \
  --with-tests
```

The Prefect flows run ingestion, dbt build, optional checks, model training, and
observability logging. They do not currently run `climate-predict-baseline`; run
the prediction command separately when the saved prediction sample should be
refreshed.

## Run Tests

Fast tests:

```bash
uv run python -m pytest -m "not integration"
```

Integration tests:

```bash
uv run python -m pytest -m integration
```

Integration tests require a built DuckDB database. If observability views are
missing, rebuild the observability dbt models before running the integration
suite.

## Run Dashboard

```bash
uv run streamlit run dashboards/streamlit/app.py
```

## Validate Saved Artifact References

```bash
python proof/validate_evidence_manifest.py
```

Refresh manifest timestamps and hashes after intentionally updating curated
artifacts:

```bash
python proof/generate_canonical_manifest.py
```

## Refresh Saved Evidence

After intentionally refreshing curated artifacts, use this sequence to align the
saved evidence set:

```bash
uv run climate-verify-local
```

`proof/test_summary.latest.json` and `proof/workflow_state.latest.json` are
generated by `climate-verify-local`.

## Cleanup

There is no long-running service to shut down unless Streamlit is running. Stop
Streamlit with `Ctrl-C` in the terminal where it is running.

Generated runtime state can be rebuilt from pipeline commands. Before deleting
anything, check whether the file is intentionally tracked as a saved artifact.
